# mBank CSV → MT940 (stage 3)

The administrator selects a complete monthly retail mBank CSV export (one per account, up to 10 accounts), matches the accounting month, selects the statement number and encoding, then downloads one `.txt` file per account. Files are processed locally, without server upload. Original CSV files and generated bytes remain in the current browser session for the later monthly package workflow.

Supported input columns: booking date, transaction date, operation description, title, counterparty, counterparty account, signed amount, balance after operation. The export must include its account number, currency, date range, opening balance and closing balance. The parser handles semicolons, quoted multiline fields, escaped quotes, UTF-8/BOM and Windows-1250. A complete calendar month is required. Account IBAN checksum, every running balance, closing balance and optional credit/debit summaries are validated in integer minor currency units. Ascending and fully reversed transaction order are accepted only after reconciliation. No transactions are silently omitted or deduplicated. Duplicate account files in a batch are rejected.

Output is **standard MT940**, with `:20:`, `:25:`, `:28C:`, `:60F:`, `:61:`, unstructured `:86:` and `:62F:`, CRLF and decimal commas. It is a conversion, not the bank's original retail MT940 profile with bank-specific numeric operation codes and repeated structured `:86:`. Select **MT940 standard** in the accounting import tool, with the selected file encoding. Compatibility with the accountant's particular application must be confirmed by importing the first generated file.

CSV does not supply a bank reference or original statement number. Transaction reference is `NONREF`; `:20:` is a deterministic converter identifier; the statement number defaults to the month number and can be changed. The transaction-date column is used for the value-date field, and the booking-date column for the entry-date field. No unavailable value dates, bank identifiers or available balances are fabricated. Standard transaction types use NCHG for fee/commission descriptions, NINT for interest and NTRF otherwise; original descriptions are retained.

The full description, title, counterparty and counterparty account are retained in up to 6 lines of 65 characters. Descriptions beyond the standard 390-character limit are rejected rather than truncated. Input limit is 10 MB per file and 50,000 operations. Windows-1250 encoding refuses unsupported characters and asks for UTF-8.

Verification:

```sh
node --test tests/mbank-mt940.test.cjs tests/mbank-ui.test.cjs
```

The user's actual sample CSV was verified locally: all 4 operations reconciled, credits 15.00 PLN, debits 15.00 PLN, opening and closing balances 0.00 PLN. Private sample account/counterparty data is not included in this repository. Tests use synthetic data and a sample account from public bank documentation.
